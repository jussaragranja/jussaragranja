# Spec — README de perfil do GitHub

> Preencha **antes** de editar o `README.md`. Este é o contrato; o README é a implementação dele.
> Ao final, o README deve passar em todos os "Critérios de aceite".

---

## 1. Objetivo de posicionamento
> Quero ser reconhecida(o) como **___**.

_(ex.: AI Advocate especializada em Qualidade de Software)_

## 2. Público-alvo
> Quem precisa comprar esse posicionamento em 10 segundos?

- [ ] Recrutadores internacionais
- [ ] Engineering Managers / Tech Leads
- [ ] Staff / Principal Engineers
- [ ] AI Leaders / CTOs
- [ ] Comunidade / pares
- [ ] Outro: ___

## 3. Proposta de valor (teste dos 10 segundos)
> O que o leitor deve **pensar** ao ler só o topo por 10s?

- Hoje ele pensa: ___
- Eu quero que pense: ___
- **Gap a fechar:** ___

## 4. Requisitos funcionais
> O que o README precisa conter.

- [ ] Headline de posicionamento
- [ ] Bio em prosa (não lista de emojis)
- [ ] Seção "No que estou trabalhando agora"
- [ ] Prova social (links, comunidade, conteúdo)
- [ ] Projetos / labs de IA
- [ ] Outro: ___

## 5. Requisitos não-funcionais
- [ ] Bilíngue espelhado (PT/EN) — ou idioma único: ___
- [ ] Imagens só de fontes estáveis (jsdelivr, shields, simple-icons)
- [ ] 1 cor de acento definida: ___
- [ ] Responsivo (sem scroll horizontal no mobile)
- [ ] Sem excesso de emoji / sem parede de logos

## 6. Anti-requisitos (evitar)
- [ ] Não parecer "apenas QA Automation" / executor
- [ ] Não usar "explorando", "estudando" (verbos de aprendiz)
- [ ] Não virar lista de tecnologias sem narrativa
- [ ] Outro: ___

## 8. Critérios de aceite (checklist de validação)
- [ ] Teste dos 10s: leitor identifica o posicionamento correto
- [ ] Existe narrativa, não só lista de tecnologias
- [ ] Verbos de construção, não de aprendiz
- [ ] Paridade total PT/EN (se bilíngue)
- [ ] Zero links/imagens quebradas
- [ ] Âncoras validadas no GitHub renderizado
- [ ] Coerência com LinkedIn / posicionamento profissional
